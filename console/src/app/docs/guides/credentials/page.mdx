# Credentials & Secrets

Inject API keys and tokens into sandboxes without exposing them in code or [sandbox environment variables](/docs/guides/environment).

## How It Works

1. **Create a secret** — your API key is encrypted server-side with KMS
2. **Bind a credential** — associate the secret with a destination domain and HTTP header
3. **Automatic injection** — the egress proxy intercepts matching outbound requests and injects the header

The secret value never enters the sandbox. Code inside the sandbox makes normal HTTP requests; the proxy handles authentication transparently.

## Create a Secret

<CodeTabs
  ts={`import { Sandbox } from "@sandbox-platform/sdk";

const { id: secretId } = await Sandbox.createSecret({
  value: process.env.OPENAI_API_KEY!,
  name: "openai-key",
});`}
  python={`import os
from sandbox_platform import Sandbox, CreateSecretRequest

secret = Sandbox.create_secret(CreateSecretRequest(
    value=os.environ["OPENAI_API_KEY"],
    name="openai-key",
))`}
/>

Secrets are immutable. To rotate a key, create a new secret and rebind credentials.

## Bind a Credential

<CodeTabs
  ts={`await sandbox.createCredential({
  secret_id: secretId,
  destination: "api.openai.com",
  header_name: "Authorization",
  header_format: "Bearer {value}",
});`}
  python={`from sandbox_platform import CreateCredentialBindingRequest

sandbox.create_credential(CreateCredentialBindingRequest(
    secret_id=secret.id,
    destination="api.openai.com",
    header_name="Authorization",
    header_format="Bearer {value}",
))`}
/>

The `destination` field matches outbound requests by domain. When a request to `api.openai.com` leaves the sandbox, the egress proxy injects the `Authorization: Bearer <key>` header automatically.

### Header Format

The `header_format` field controls how the secret value is inserted into the header:

| Format | Result |
|---|---|
| `{value}` (default) | The raw secret value |
| `Bearer {value}` | `Bearer sk-abc123...` |
| `Basic {value}` | `Basic dXNlcjpwYXNz...` |
| `Token {value}` | `Token ghp_abc123...` |

## Multiple Credentials

A sandbox can have multiple credential bindings, each targeting a different destination:

<CodeTabs
  ts={`// OpenAI
await sandbox.createCredential({
  secret_id: openaiSecretId,
  destination: "api.openai.com",
  header_name: "Authorization",
  header_format: "Bearer {value}",
});

// GitHub
await sandbox.createCredential({
  secret_id: githubSecretId,
  destination: "api.github.com",
  header_name: "Authorization",
  header_format: "Token {value}",
});`}
  python={`# OpenAI
sandbox.create_credential(CreateCredentialBindingRequest(
    secret_id=openai_secret.id,
    destination="api.openai.com",
    header_name="Authorization",
    header_format="Bearer {value}",
))

# GitHub
sandbox.create_credential(CreateCredentialBindingRequest(
    secret_id=github_secret.id,
    destination="api.github.com",
    header_name="Authorization",
    header_format="Token {value}",
))`}
/>

## Deleting Credentials

<CodeTabs
  ts={`await sandbox.deleteCredential(credentialId);`}
  python={`sandbox.delete_credential(credential_id)`}
/>

<Callout type="warning">Deleting a credential takes effect immediately. Any in-flight requests that haven't been proxied yet will not have the header injected.</Callout>
